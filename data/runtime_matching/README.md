# 智能肌肉护膝 U 盘运行版匹配数据库

生成时间：2026-07-18 12:47:14

这不是压缩包，也不是只存路径索引。这个目录可以直接拷进 U 盘，用来做你们说的功能：

> 用户实际使用时，先采集一小段当前肌电数据，提取 RMS、MAV、WL、ZC、SSC、姿态变化等特征，再到数据库里寻找最相近的历史肌电片段或人员类型，用相似类型辅助判断当前疲劳状态。

## 为什么这个库比完整原始库小

470MB 的 U 盘装不下完整外部原始波形的解压版，因为公开 MAT 数据整理成原始 CSV 后大约 2GB。

实际运行匹配时也不应该扫描几 GB 原始波形。正确做法是：

```text
原始波形 -> 离线提取特征 -> U盘保存可匹配特征表 -> 实际使用时快速查相似样本
```

所以这个目录保存的是“可实际匹配的特征数据库”，不是完整原始波形仓库。

## 文件说明

- `runtime_units.csv`
  - 所有可匹配样本单元。
  - 包含你们自采数据和外部公开数据。
- `runtime_units_normalized.csv`
  - 已做归一化的匹配特征表。
  - 实际匹配建议用这个。
- `person_profiles.csv`
  - 每个 `person_id` 的人员类型摘要。
- `runtime_matching_database.sqlite`
  - SQLite 版本，方便 Python 查询。
- `normalization_stats.json`
  - 特征标准化参数。
- `match_query.py`
  - 示例匹配脚本。
- `query_example.json`
  - 当前用户输入特征示例。

## 能不能实现你们要的功能

可以实现第一版“相似个体/相似肌电片段匹配”。

但要讲清楚边界：

1. 你们自采数据和当前设备同源，最适合用于疲劳等级参考。
2. 外部公开数据能扩大双通道肌电动作样本量，但它没有疲劳标签、没有身高体重腿围，所以不能单独当作疲劳标签来源。
3. 因为外部数据单位和你们板端日志单位不同，库里通过 `feature_schema` 和归一化特征做兼容，不能直接拿原始 RMS 数值硬比。

## 使用示例

在这个目录下运行：

```powershell
python match_query.py query_example.json device_core 5
```

`device_core`：只匹配你们自采数据，适合疲劳判断。

```powershell
python match_query.py query_example.json mixed_shape 5
```

`mixed_shape`：同时参考外部公开肌电样本，适合展示“数据库扩容后的相似肌电检索”。

答辩时建议这样说：

> 我们没有把所有原始波形都放进运行库，而是将原始肌电离线提取为可比较特征。设备或上位机只需把当前用户的一小段肌电转成同样的特征向量，就能在 U 盘数据库中检索最相近的历史样本和人员类型，从而实现个体化疲劳判断参考。
