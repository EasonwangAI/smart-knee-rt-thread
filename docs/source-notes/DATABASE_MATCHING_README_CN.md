# 智能护膝数据库匹配版使用说明

## 1. 这个版本是什么

本工程 `test_pro719_dbmatch` 以 2026-07-18 晚已经确认圆屏正常显示的
`test_pro7_18_working_lcd_ok_20260718` 为底版。圆屏驱动 `gc9a01.c` 未修改。

新增的数据路径为：

1. STM32 每秒取得 20 组实时 RMS、MAV、WL、ZC、SSC、膝部角度和肌肉激活状态。
2. 肌电校准进入 `RUN` 后，保存最近 5 秒（100 组）的滚动特征。
3. 至少有 20 组处于肌肉激活状态时，扫描数据库并寻找 Top-5 相似样本。
4. 允许同一受试者的多个相近时间窗进入 Top-5，便于已入库受试者演示身份匹配。
5. 有明确疲劳标签的最近 5 条样本按距离加权投票，得到参考分和置信度。
6. 数据库最多占最终疲劳分的 25%，原板端肌电算法仍是主要判断依据。
7. 每 15 秒使用新的滚动窗口重新匹配一次，以跟踪当前状态变化。

固件内置了 31 个经过异常值筛除的“人员类型 × 疲劳等级”稳健中位数原型。
因此即使不插存储卡，设备也能完成 Top-5 匹配。若检测到完整数据库文件，系统
会自动改用 1734 条完整运行库。

自动演示模式使用 `device_core`，优先检索其中 870 条由同一套护膝硬件采集、且
带疲劳标签的样本，这样更容易命中已经入库的演示者。其余 864 条公开数据仍保留
在完整库中，用于离线分析或手动混合检索，不直接抢占自动匹配结果。

公开 MAT 数据中没有可靠疲劳等级的记录只参与“信号形态相似度”，不会参与
疲劳等级投票，避免把无标签数据当成正确答案。

## 2. 可选：使用完整数据库

将本工程中的整个文件夹：

`storage_payload/smart_knee_runtime_db`

复制到 FAT32 SD 卡根目录。复制后应当存在：

`/smart_knee_runtime_db/runtime_units_normalized.csv`

以及：

`/smart_knee_runtime_db/DB_compatible/`

不插卡时会使用固件内置的 31 个紧凑原型，功能仍可演示。

注意：当前 BSP 启用的是 SDIO，没有启用 USB Host。普通 U 盘不能直接作为 STM32
运行时数据库使用；电脑端备份可以继续放 U 盘，若要扫描完整库则使用 SD 卡。

## 3. 上电后如何验证

1. 正常上电，先完成原程序的静息校准和主动收缩校准。
2. 进入 `RUN` 后开始深蹲，让肌肉至少实际发力 1 秒。
3. 约 5 秒后，串口会出现 `DB,TOPK,1` 到 `DB,TOPK,5`。
4. 随后会出现 `DB,RUNTIME_AUTO`，其中包含 `db_score` 和 `confidence`。
5. 圆屏底部出现 `EMG:OK+DB` 或 `EMG:ALERT+DB`，说明数据库已参与判断。
6. `FAT` 显示的是融合后的 0-100 疲劳分；达到阈值时仍按原方式触发马达。

若串口出现 `DB,RUNTIME_BUILTIN,count=31`，表示当前使用内置紧凑库，这是正常
状态。插入完整数据库后，匹配结果中的 `rows` 应为 1734。

若完整库路径配置有误，系统会自动退回内置库，不会导致匹配功能停止。

若要检查完整库，目标路径是：

`/smart_knee_runtime_db/runtime_units_normalized.csv`

如果插卡后仍显示 `DB,RUNTIME_BUILTIN`，说明 SD 卡没有正确挂载，或者数据库
文件夹没有放在卡的根目录。

## 4. 重要边界

本功能是小样本相似检索加保守校准，不等同于临床疲劳诊断。数据库参考分不会
替代原随机森林/肌电特征评分，只会在匹配可信时进行有限修正。
