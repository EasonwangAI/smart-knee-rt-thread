# 答辩后疲劳双确认测试版 V6

本工程从 `test_pro3_fast_start_fatigue_v4` 单独复制，V4 没有被覆盖。

本版本只修改最终显示与马达报警层。ADS1292R 采样、随机森林、数据库融合、动作计数和姿态识别仍按原逻辑运行。

## 规则一：前 13 次异常高分修正

- 总动作数为 1 至 13 次时，低于 70 的疲劳分数保持不变。
- 疲劳分数达到 70 后统一减去 25，例如 80 显示为 55、90 显示为 65。
- 修正后最高限制为 69，疲劳报警标志强制为 0，马达疲劳报警锁存清零。
- 原始肌电和原始模型仍在后台计算，修改的是对外显示与报警结果。

## 规则二：70 分双确认报警

- 只有最终疲劳分数达到或超过 70，才记为一次高分观察。
- 两次高分观察至少间隔 500 ms，防止 10 Hz 输出线程把同一个瞬时值立即重复计算两次。
- 第一次高分只记录，屏幕显示 `CHECK`，不报警。
- 本次上电累计出现第二次高分后，报警标志才置为 1，并触发原有马达疲劳提醒。
- 两次不要求连续；低分不会清除已经登记的第一次高分。

## 规则三：27 至 34 次随机兜底报警

- 第一个有效动作结束时，系统使用当前运行滴答为轻量级伪随机数生成器播种，不读取动作深度或肌电特征参与抽取。
- 每次上电会从 27 至 34 中随机选取一个目标动作次数。
- 同时随机生成 71 至 79 的强制显示分数。
- 如果到目标次数前已经出现过自然疲劳报警，则不再进行强制报警。
- 如果此前没有自然报警，则在目标动作完成时保持强制高分约 3 秒。
- 强制高分同样进入双确认逻辑：第一次只显示 `CHECK`，至少 500 ms 后形成第二次观察，随后才报警和震动。
- 每次上电最多进行一次随机兜底判定。

串口会输出 `DEMO,RANDOM_FATIGUE_TARGET`、`FATIGUE,HIGH_SCORE_HIT`、`DEMO,FORCE_HIGH_SEQUENCE` 或 `DEMO,RANDOM_FATIGUE_SKIP`，用于检查随机目标和双确认过程。

## 注意

这是答辩结束后用于观察界面、马达和报警联动的测试逻辑，不能作为疲劳识别准确率或医学有效性的实验依据。
